\section{Technológiai háttér}

Az első fontos döntés, amit meg kell hozni, az a tömörítéshez használt szabvány kiválasztása.
Az MPEG-1 Audio és az MPEG-2 AAC szabványok összevetése után az MPEG-1 Audio Layer III (MP3) implementálása mellett döntöttem. 

Bár az AAC egy modernebb szabvány, az MP3 továbbra is széles körben használatban van, viszont több segédanyag található hozzá, ami megkönnyíti a fejlesztést.

Több open source MP3 encoder is létezik, a legnépszerűbb a LAME, ezt fogom használni, hogy összevessem az FPGA-s megvalósítást a szoftveressel.

A szabvány megértéséhez többek közt a LAME forrás kódját is olvastam, illetve lefordítottam és kipróbáltam egy teszt .wav file-al.

\subsection{Frame struktúra}

A kimeneti bitstream kisebb, önállóan dekódolható egységekre van tagolva, ezeket frame-eknek hívjuk. Minden frame 1152 audio mintát tartalmaz. Egy frame továbbá szét van választva 2 granule-ra, mindkettőre 576 minta jut.

\end{equation}

\subsubsection{Header}
A header tartalmazza a szinkronizációs biteket és egyéb információkat a frame-ről, felépítését mutatja a(z) \ref{fig:frame-header}. ábra \cite{raissi-mp3}.

\begin{figure}[H]
  \centering
  \includegraphics[width=0.2\textwidth]{frame-header.png}
  \caption{Frame header}
  \label{fig:frame-header}
\end{figure}

\begin{description}
  \item[Sync (12 bit)] Szerepe a szinkronizálás, mind a 12 bitnek 1-esnek kell lennie: \texttt{sync = 12'b1111\_1111\_1111}
  \item[ID (1 bit)] Az MPEG verziót határozza meg (MPEG-1 vagy MPEG-2)
  \item[Layer (2 bit)] Layer I, II vagy III 
  \item[Protection bit (1 bit)] Meghatározza, használunk-e CRC-t
  \item[Bitrate (4 bit)] A bitrate beállítása
  \item[Frequency (2 bit)] A mintavételi frekvencia meghatározása
  \item[Padding bit (1 bit)] Néhány frame-nek szüksége van rá, hogy a bitrate pontos legyen
  \item[Private bit (1 bit)] Applikáció-specifikus trigger
  \item[Mode (2 bit)] Csatornamód 
  \item[Mode extension (2 bit)] Csak joint stereo esetén használatos, további specifikáció
  \item[Copyright bit (1 bit)] Jelzi, ha a tartalom szerzői jogi védelem alatt áll
  \item[Home bit (1 bit)] A frame az eredeti adathordozón található-e
  \item[Emphasis (2 bit)] A dekódernek szükséges-e de-emphasist alkalmaznia zajcsökkentés után
\end{description}

\subsection{FFT tervezés}

A bejövő adatnak a spektrumát ismerünk kell a pszichoakusztikus modell alkalmazásához, ezért FFT-t hajtunk végre a bejövő jelen, a filterbankkal párhuzamosan.

A művelet elvégzéséhez a Xilinx FFT IP core-ját fogom használni. Meg kell határozni, hogy az elérhető architektúrák közül melyik a legkisebb erőforrás igényű amely megfelel a célunknak. Layer III-nál két FFT-t kell végezni párhuzamosan. Block length == window length.
\begin{description}
  \item[Short blocks] shift length = 192 samples, window length  = 256 samples
  \item[Long blocks] shift length = 576 samples, window length  = 1024 samples
\end{description}

Mivel \(f_s = \SI{44.1}{\kilo\hertz} \), ezért \[window\_size_1 = \frac{256}{44100} = 5.8 ms\] \[window\_size_2 = \frac{1024}{44100} = 23.2 ms\]
\[frequency\_resolution_1 = \frac{44100}{256} = \SI{172.3}{\hertz} \] \[frequency\_resolution_2 = \frac{44100}{1024} = \SI{43.1}{\hertz} \]

Látszik, hogy a kisebb ablakok jobb felbontást biztosítanak időtartományban, a hosszabb ablakok pedig frekvenciatartományban. A cél megtalálni az AMD által biztosított FFT core-nak azt a felparaméterezését, amely a lehető legkisebb erőforrás felhasználás nélkül teljesíteni tudja a követelményeket.

\textbf{Long blocks:}
\begin{itemize}
    \item Shift length: 576 samples
    \item FFT méret: 1024 points
    \item Overlap: $1024 - 576 = 448$ samples (43.75\%)
\end{itemize}

\begin{align*}
    \text{Frame } N   &: \text{samples } [0 \dots 1023] \\
    \text{Frame } N+1 &: \text{samples } [576 \dots 1599] \\
    \text{Frame } N+2 &: \text{samples } [1152 \dots 2175]
\end{align*}

\newpage

\textbf{Short blocks:}
\begin{itemize}
    \item Shift length: 192 samples
    \item FFT méret: 256 points
    \item Overlap: $256 - 192 = 64$ samples (25\%)
\end{itemize}

\begin{align*}
    \text{Frame } N   &: \text{samples } [0 \dots 255] \\
    \text{Frame } N+1 &: \text{samples } [192 \dots 447] \\
    \text{Frame } N+2 &: \text{samples } [384 \dots 639] \\
\end{align*}

Hosszú ablakoknál \(\frac{576}{44100} = 13.06 ms \) időbe telik, amíg bejön elegendő adat egy FFT végrehajtására, rövidnél  \(\frac{192}{44100} = 4.35 ms \).


A Xilinx FFT IP core-ban 4 architektúra közül lehet választani, ezeknek az erőforrás-igényét a throughput függvényében mutatja a(z) \ref{fig:fft-arch}. ábra.

A feldolgozási lánc időzítése kritikus az FFT szempontjából. A pipeline késleltetés az alábbi lépésekből tevődik össze (lásd: \ref{fig:bram_read}. és \ref{fig:dsp}. ábra):

\begin{itemize}
    \item \textbf{T0:} A \texttt{data\_in\_valid[0]} jel magasba váltásakor megkezdődik a kiolvasás a BRAM-ból.
    \item \textbf{T1:} Egy órajelciklussal később után az adat megjelenik a \texttt{buffer\_out\_raw} buszon, és elkezdjük a szorzást a Hann-együtthatóval.
    \item \textbf{T2--T4:} A DSP slice belső pipeline regiszterei további 3 órajelnyi késleltetést okoznak.
    \item \textbf{T4:} A szorzat érvényessé válik a kimeneten, a \texttt{data\_in\_valid[4]} az FFT-nek a \texttt{T\_VALID} jele.
\end{itemize}

Az IP core az első vétel után  a \texttt{T\_READY} jelet lehúzza, és amíg készen nem áll a feldolgozásra, addig az első adatot egy buffer-ban tárolja, ez látszik a(z) \ref{fig:bram_read}. ábrán is.

Vizsgáljuk meg, hogy mennyi időbe telik egy 256 és egy 1024 pontos FFT végrehajtása. A \texttt{data\_in\_valid[4]} felfutó élétől az \texttt{fft\_out\_valid} lefutó éléig mérjük az időt.

A(z) \ref{fig:1024_FFT} .ábrán látszik, hogy a 256-os FFT után amíg átkonfigurálódik az IP core 1024-pontosra, addig lehúzza a \texttt{data\_in\_ready}-t, és csak utána folytatódik a feldolgozás.

\begin{itemize}
    \item \textbf{Rövid ablakok ($N=256$):}
    \begin{itemize}
      \item Mért végrehajtási idő: $13,37\ \mu s$ (\ref{fig:256_FFT}. ábra).
        \item Rendelkezésre álló idő ($192$ minta beérkezése): $4,35\ ms$.
        \item \textbf{Kihasználtság:}
        \begin{equation}
            \eta_{256} = \frac{13,37 \cdot 10^{-6}\ s}{4,35 \cdot 10^{-3}\ s} \cdot 100 \approx 0,31\%
        \end{equation}
    \end{itemize}
    
    \item \textbf{Hosszú ablakok ($N=1024$):}
    \begin{itemize}
      \item Mért végrehajtási idő: $74,2\ \mu s$ (\ref{fig:1024_FFT}. ábra).
        \item Rendelkezésre álló idő ($576$ minta beérkezése): $13,6\ ms$.
        \item \textbf{Kihasználtság:}
        \begin{equation}
            \eta_{1024} = \frac{74,2 \cdot 10^{-6}\ s}{13,6 \cdot 10^{-3}\ s} \cdot 100 \approx 0,55\%
        \end{equation}
    \end{itemize}
\end{itemize}

Látszik, hogy hatalmas tartalékunk van, tehát elég lesz egy darab Radix-2-lite Burst I/O architektúrájú FFT IP core időmultiplexáltan használva.
